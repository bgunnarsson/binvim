# Editing

- **Modal editing** — normal / insert / visual (charwise, linewise, blockwise) with operators, text objects, marks, registers, dot-repeat, undo/redo, and macros.
- **Multi-cursor (mirrored, real)** — `Ctrl-click` in Normal mode adds a secondary cursor at the click position; cursors render as Lavender blocks. Enter Insert via `i` (anchored) or `a` (shifts each cursor by +1); typing and Backspace mirror at every site simultaneously (bottom-up edit order keeps indices stable). `Esc` collapses; a plain (non-Ctrl) click also collapses.
- **Multi-selection (`Ctrl-N`)** — Sublime-style. In Visual-char mode, `Ctrl-N` finds the next literal-text occurrence of the current selection and adds it as a parallel selection. Repeat to keep adding. `d`/`c`/`y` apply across every selection; `c` lands in Insert mode with a mirrored cursor at every former selection start.
- **Visual-block mode (`Ctrl-V`)** — third visual kind alongside char and line. Rectangular selection across a line span; `d`/`c`/`y` apply column-wise per row, `>`/`<` fall back to indent / outdent over the line range.
- **Reselect (`gv`)** — brings back the last Visual selection: same kind, cursor on the same end, moved along with any edits since. Inside Visual it swaps the current selection with the previous one.
- **Surround operations** — `ds<char>` strips the surrounding pair, `cs<old><new>` swaps it, visual `S<char>` wraps the selection, `ys{motion}<char>` wraps a motion or text object (`ysiw)`), `yss<char>` the line, and `yS` / `ySS` put the pair on lines of their own. Pair chars: `(/)/b`, `[/]`, `{/}/B`, `<`, `"`, `'`, `` ` ``.
- **Case operators** — `gu` / `gU` / `g~` / `g?` lowercase, uppercase, toggle or ROT13 a motion or text object (`gUiw`, `g~$`); `guu`, `gUU`, `g~~` and `g??` take the line, and Visual `u` / `U` / `~` / `g?` the selection, block mode included. No register is touched.
- **Joining lines** — `J` joins the next line with one space between, `3J` joins three lines, and `gJ` joins without adding or removing any whitespace. Visual `J` / `gJ` join every line the selection covers.
- **Replace mode (`R`)** — typing goes over the text and on past the line end; `Backspace` puts back what it replaced, and `3R` types the text three times. Visual `r<char>` replaces every selected character, block mode included.
- **Putting (`gp`, `]p`)** — `gp` / `gP` put like `p` / `P` and leave the cursor just after the text; `]p` puts lines below re-indented to the cursor's line, and `[p` above.
- **Re-indent (`=`)** — `==`, `=ip`, `=%` and Visual `=` re-indent lines by the rules Enter uses: a level deeper after a line that opens a block, a level shallower for one that starts by closing it.
- **Re-flow (`gq`, `gw`)** — `gqq`, `gqip` and Visual `gq` fill paragraphs to `.editorconfig`'s `max_line_length` (79 without one), keeping a comment's `//` / `#` marker on every line; `gw` leaves the cursor where it was.
- **Filter (`!`)** — `!{motion}`, `!!` and Visual `!` open `:` with the lines' range (`:5,7!`); the command you type gets them on stdin and its output replaces them, while a failing command leaves them alone. `:{range}!cmd` works typed directly.
- **Numeric `Ctrl-A` / `Ctrl-X`** — increment / decrement the next number on the current line. Recognises decimal, `0x…`, `0b…`, `0o…`, with optional leading `-`. Preserves leading zeros. In Visual they change the first number on each selected line, block selections included, and `g Ctrl-A` / `g Ctrl-X` count up line by line (1, 2, 3…).
- **Smart indent on Enter** — copies the current line's leading whitespace and adds one indent unit after `{ [ ( :` `=>` `->`. Pressing Enter inside an auto-paired `{|}` splits the pair into three lines with the cursor on the indented middle.
- **Insert-mode word / line-start delete shortcuts.** `Alt`/`Option`+`Backspace` deletes the previous word (peels trailing whitespace, then one homogeneous run of word chars or punctuation — same as macOS Option-Delete). `Cmd`/`Super`+`Backspace` deletes from the cursor back to column 0. `Ctrl`+`Backspace` aliases to the word-delete for terminal users without a usable Option key, and Vim's `Ctrl-W` does the same word-delete. `Ctrl-U` deletes back to the indent, and a second press from the indent takes the indent too. None of them delete across a line break mid-line; from column 0 they join the line onto the one above, like Backspace.
- **Registers** — `"a`–`"z` name a register for any yank, delete or put, and `"A`–`"Z` append to one. Vim's own fill themselves: `"0` holds the last yank, `"1`–`"9` shift down as each delete of a line or more arrives, `"-` keeps the smaller ones, and the read-only `".` / `"%` / `"#` / `":` / `"/` give the last insert, the current and alternate file, the last command line and the last search. `"_` is the black hole, `"+` / `"*` the system clipboard, and `"=` evaluates an arithmetic expression for `p`. `:reg` lists them all.
- **Macros** — `q{a-z}` records until the next `q`, `@{a-z}` replays it, and `@@` replays the last one again; `Q` replays the last macro too. `@:` runs the last `:` command line again, with a count (`3@:`) that stops at the first error, as in Vim. A macro's keys replay through the same path as typing, so `[keymaps]` mappings inside one still apply.
- **Insert-mode register paste** — `Ctrl-R {reg}` inserts a register at the cursor: `a`–`z`, `0`–`9`, `"` (unnamed), `+` / `*` (system clipboard), `-` (the last small delete), or the read-only `.` (last insert), `%` / `#` (current / alternate file), `:` (last command line) and `/` (last search). The text goes in literally — no auto-pair, no re-indent — and multi-line registers make real lines. A `"` marks the cursor while the register name is pending; `Esc` cancels. `Ctrl-A` inserts the last inserted text (`".`). `Ctrl-R =` asks for an arithmetic expression and inserts its value; `"=` does the same for `p`.
- **Insert `Ctrl-X` completion** — `Ctrl-X Ctrl-N` / `Ctrl-P` complete from the buffer's words (nearest first), `Ctrl-X Ctrl-L` whole lines, `Ctrl-X Ctrl-F` file paths — in the same popup as LSP completion, narrowing as you type.
- **Digraphs** — `Ctrl-K {a}{b}` in Insert enters a special character: `a:` → `ä`, `th` → `þ`, `d-` → `ð`, `->` → `→`, `Eu` → `€`, `a*` → `α` (Vim's RFC 1345 codes, either way round). `:digraphs` lists the set.
- **`Ctrl-C`** — leaves Insert, Visual, a pending operator or count, and the `:` / `/` prompts, as `Esc` does; from Insert it keeps nothing for `.`, as in Vim.
- **Command-line keys** — on the `:` and `/` prompts, `Ctrl-R {reg}` inserts a register, `Ctrl-R Ctrl-W` / `Ctrl-R Ctrl-A` the word / WORD under the cursor; `Ctrl-W` / `Ctrl-U` delete the word before the cursor / everything before it; `Ctrl-B` / `Ctrl-E` go to the start / end; `Ctrl-P` / `Ctrl-N` walk the history like `<Up>` / `<Down>`.
- **Command-line window** — `q:` / `q/` / `q?` open a split below listing the ex / search history, oldest first, with an empty line at the bottom. Edit it in Normal mode; `<CR>` runs the line under the cursor, `Ctrl-C` or `:q` closes it.
- **Visual-block insert** — in `Ctrl-V` block mode, `I` / `A` insert before / after the block on every row at once (`A` pads rows that stop short), `$A` appends at each row's own end, and `.` repeats it on a block of the same size.
- **Visual uppercase keys** — `Y` / `D` / `X` / `C` / `R` take whole lines from any Visual mode, as in Vim; in block mode `D` / `C` run to each row's end (so do `$` blocks), and `O` jumps to the other corner. `Ctrl-C` leaves Visual like `Esc`.
- **Insert-mode indent / outdent** — `Ctrl-T` adds one indent unit (per `.editorconfig`) to the current line and `Ctrl-D` removes one, keeping the cursor on the same character of text. `Ctrl-T` works on a blank line too.
- **Insert-mode literal insert** — `Ctrl-V` inserts the next key as it is: `Ctrl-V Tab` is a real tab under space indentation, `Ctrl-V (` skips auto-pair. `Ctrl-V u00e9` inserts a character by code, as do `U` (8 hex digits), `x` (2), `o` (3 octal) and up to 3 decimal digits. Control characters are refused, since binvim can't display them yet.
- **Insert-mode copy from above / below** — `Ctrl-Y` inserts the character at the cursor's column from the line above, `Ctrl-E` the one from the line below; repeat to copy a run.
- **Insert-mode one-shot Normal command** — `Ctrl-O` runs one Normal-mode command and comes back to Insert: `Ctrl-O dd`, `Ctrl-O 0`, `Ctrl-O :w`. The mode chip reads `(INSERT)` until the command finishes. Pressed at the end of a line, it comes back to the end of the line, and so does `Ctrl-O $`.
- **HTML tag auto-completion** — typing `>` after `<div` writes `<div>|</div>`. Self-closing tags, void elements, generics (`Array<T>`), comments and declarations all skipped. Active in `.html`, `.cshtml`, `.razor`, `.jsx`, `.tsx`, `.vue`, `.svelte`, `.astro`, `.xml`, `.md`.
- **Bracket and HTML-tag matching** — when the cursor is on (or just past) a bracket or anywhere inside an HTML tag, the matching partner highlights with a Surface2 background + bold. Works through arbitrary nesting. `%` jumps to the partner — from the first bracket at or after the cursor on the line, or from an HTML tag to its pair — and works with operators (`d%`); `N%` goes to the line N percent of the way through the file.
- **Paragraph motions** — `}` / `{` move to the empty line after / before the paragraph; a count skips that many and a run of empty lines counts as one. From the start of a line, `d}` / `y}` / `c}` work on the paragraph's whole lines and leave the blank one, as in Vim. The `ip` / `ap` text objects take the paragraph (plus its trailing blank lines for `ap`) line-wise — `dap`, `cip`, `yip`, `vip` — and treat whitespace-only lines as blank.
- **Sentence motions** — `)` / `(` move to the start of the next / current sentence: one ends at `.`, `!` or `?` (plus any closing brackets or quotes) followed by whitespace, and an empty line starts one of its own. Counts and operators work (`d)`), and both go in the jump list. The `is` / `as` text objects take a sentence, `as` with the space after it — `das`, `cis`, `vis`.
- **Tag objects** — `it` / `at` take an element's content, or the element with its tags (`dit`, `vat`), in any buffer; a count reaches outer elements.
- **Argument objects** — `ia` / `aa` take a comma-separated argument inside `()`, `[]` or `{}` (`aa` with one comma next to it), ignoring commas in nested brackets and quoted strings.
- **Bracket motions** — `]d` / `[d` jump to the next / previous diagnostic and show its message; `[(` `[{` `])` `]}` go to the unmatched bracket around the cursor, after an operator too (`d])`).
- **Syntax objects** — `af` / `if` take the function around the cursor (or its body) and `ac` / `ic` the class, struct or impl, from the tree-sitter parse — Rust, TS/JS, Python, Go, C#, Lua, C and C++.
- **Search** — `/` and `?` take Vim's regex syntax (`\(…\)`, `\|`, `\+`, `\{n,m}`, `\<` / `\>`, `\s` / `\d` / `\w`, `[…]`, `\zs` / `\ze`, `\v` / `\V`) with smart case — an upper-case letter makes it case-sensitive, `\c` / `\C` decide outright — and every match is highlighted in full. `*` / `#` search the word under the cursor as a whole word, `g*` / `g#` as bare text, and `n` / `N` take a count. An offset after the pattern moves the cursor off the match — `/pat/e` to its last char, `/pat/e+1` / `/pat/s-1` / `/pat/b` counted from its ends, `/pat/+2` two lines down — and `n` / `N` keep it; `//` searches the last pattern again with a new offset. `gn` / `gN` select the next match, and after an operator act on it — `cgn` then `.` changes one match after another. Matches highlight as you type the pattern and the view follows the first one; `Esc` puts the cursor back.
- **Line and column motions** — `<CR>` / `+` and `-` go N lines down / up to the first non-blank, `N_` to the first non-blank N−1 lines down (so `d_` is `dd`), and `N|` to column N. All of them work with operators. Long lines scroll sideways rather than wrap, so `g0` / `g^` / `gm` / `g$` go to the first char / first non-blank / middle / last char on screen, `gM` to the middle of the line, and `gj` / `gk` move like `j` / `k`.
- **Marks** — `m{a-z}` sets a mark, `'` jumps to its line and `` ` `` to its exact spot. Vim's own marks work too: `''` goes back to before the latest jump, `'.` to the last change, `` `^ `` to where Insert was last left, `'[` / `']` to the start and end of the last change or yank, and `'<` / `'>` to the last Visual selection. Marks move with the text as you edit, and keep their line and column through format-on-save and a reload from disk. `:marks` lists them, and `:jumps` lists the jump list. Uppercase marks (`mA`) remember their file too: `'A` from any other file switches back to it at the mark, for the rest of the session.
- **Insert where you left off (`gi`)** — goes back to where Insert was last left, following any edits since, and starts Insert there.
- **Change list** — `g;` goes back through the places you changed, newest first, and `g,` forward again; a count skips that many. Changes on one line count once, each buffer keeps its last 100, and the places move with the text. `:changes` lists them.
- **Code folding** — indent-based folds, toggled with `za`/`zo`/`zc`, with `zR`/`zM` to open/close all. Folded blocks render as `⏷ N lines`. `zj` / `zk` move between folds, `zv` opens what hides the cursor, `zO` / `zC` / `zA` work recursively, and `zm` / `zr` / `zx` set and re-apply the fold level.
- **`z` scrolling** — `z<CR>` / `z.` / `z-` put the cursor's line at the top / middle / bottom with the cursor on its first non-blank, and `zs` / `ze` scroll sideways to put the cursor at the left / right edge.
- **Info and open-under-cursor keys** — `Ctrl-G` (file, length, position), `g Ctrl-G` (column / line / word / byte counts, or the selection's), `ga` (character code), `gx` (open the URL under the cursor), `gf` / `<C-w>f` (open the file under the cursor, `path:line` jumping to the line; `<C-w>f` in a split), `gI` (insert at column 0) and `Ctrl-L` (redraw).
- **Git gutter + hunks** — leftmost gutter column shows working-tree changes against the git index: Green `▎` for added lines, Yellow `▎` for modified, Red `▁` for the line just below a deletion. Status line gains a `+A ~M -D` counter next to the branch name. `]h` / `[h` jump to next / previous hunk; `<leader>hp` previews the hunk under the cursor in a hover popup (three lines of surrounding context). `<leader>hs` stages the hunk via `git apply --cached`, `<leader>hu` unstages, `<leader>hr` discards (refuses while the buffer is dirty so unsaved edits can't be lost). Refreshed on save, on buffer switch, on initial open, and after any stage / unstage / reset.
- **Inline git blame** — `:Gblame` toggles per-line virtual text at end-of-line: author • relative age (`3d`, `2w`, `4mo`) • short SHA, in muted italic. Parsed from `git blame --porcelain`. Per-buffer toggle. Suppressed on rows that already show an inline diagnostic.
- **Persistent undo** — undo history is serialised per file under `~/.cache/binvim/undo/<hash>.json` on save and reloaded on the next session, keyed by content hash so external edits invalidate stale history. The directory is readable only by you, since each file holds your text, and history for a file not saved in 90 days is removed at startup. Within a session undo is a tree: an edit after `u` keeps what you undid, `g-` / `g+` walk every state in the order it was made, and only the current branch is saved. `:earlier` / `:later` go back and on by steps, time (`10s`, `5m`, `1h`) or file writes (`1f`), and `:undolist` lists the branches.
- **Cursor restored on reopen** — where you were in a file is written to `~/.cache/binvim/cursor/<hash>.json` when you leave the buffer, quit, or the terminal goes away, and the file opens there next time — after `:q!` too, since the entry is keyed by the text on disk. A file changed outside binvim opens at the top instead, as does one that `:S` or an LSP rename changed without showing it. Entries not written in 90 days are removed at startup.
- **System-clipboard yank + paste** — `y`, `yy`, `Y`, `:y`, visual yank, and the implicit yank on `d`/`c`/`x` mirror to the OS clipboard via `arboard` whenever they target the unnamed register. `p` / `P` (Normal *and* Visual mode) read from the OS clipboard first — anything you `Cmd-C`'d in another app wins over the in-memory yank. Named registers (`"ay`) stay local.
- **Visual-mode paste** — `p` / `P` over a selection (word / multi-line / block) swaps the selection with the register's contents. Linewise content over a charwise selection drops its trailing newline so paste doesn't open a stray blank line.
- **Yank flash** — yanked range flashes a Catppuccin Peach background for 200ms so you see what's been picked up.
- **Horizontal scrolling** — long lines scroll automatically as the cursor moves past the edge; trackpad / mouse-wheel horizontal events scroll without moving the cursor; Vim-style `zh` / `zl` (1 col) and `zH` / `zL` (half-width) work too.
- **Double-click to select word, drag to extend by words** — a second left-click at the same buffer position within 350 ms expands to the inner word and enters Visual-char. Continue holding and drag to grow or shrink the selection a word at a time; the cursor snaps to whole-word boundaries and only jumps once a new word is crossed (dragging through whitespace keeps the previous boundary).
- **Whitespace markers** — every space, tab, non-breaking space, and end-of-line surface as a muted glyph (`·`, `→`, `⎵`, `¬`). Configurable.
- **Format on save / on-demand** — `<leader>f` or `:fmt` runs the right tool per extension. biome for JS / TS / JSX / TSX / JSON / JSONC; csharpier for `.cs`; `gofmt` / `goimports` for `.go`; `ruff format` (or `black` as fallback) for `.py`; `clang-format` for `.c` / `.h` / `.cpp` / `.cc` / `.hpp` / `.cxx` / `.hxx`; `shfmt` for `.sh` / `.bash` / `.zsh`; `stylua` for `.lua`; Prettier (project-local `node_modules/.bin/prettier` first, then global) for the file types biome doesn't currently format — `.md` / `.mdx` / `.vue` / `.svelte` / `.html` / `.htm` / `.css` / `.scss` / `.less` / `.yaml` / `.yml` / `.graphql` / `.gql`; `taplo format` for `.toml`; `rufo` for `.rb`; `php-cs-fixer` for `.php` (temp-file dance — no stdin mode); `google-java-format` for `.java`; `zig fmt` for `.zig`; `nixfmt` (or `alejandra`) for `.nix`; `mix format` for `.ex` / `.exs`; `ktfmt` for `.kt` / `.kts` (temp-file dance); `sql-formatter` for `.sql`; `.editorconfig` indent reflow for `.cshtml` / `.razor` (csharpier rejects those, so we fall through). `.editorconfig` directives (final newline, trailing whitespace) apply on every save regardless of extension.
- **Auto-reload on disk change** — when an open file changes externally and the buffer isn't dirty, binvim notices via mtime poll and reloads with a status note.
- **Writes that can't lose work** — `:w` writes a temp file beside the original and renames it over, so a write that fails partway (a full disk) leaves the old file whole; symlinks, permissions and hard links are kept. `:w` refuses, and `:w!` writes anyway, when the file was changed on disk since it was read (a `git pull` under unsaved edits), when `:w {file}` names another file that already exists (`E13`), and when the file wasn't valid UTF-8 — opening one says so, since its invalid bytes show as `�` and writing makes that permanent. A formatter that prints nothing for a non-empty buffer is reported as a failure instead of emptying the file.
- **Recovery after a crash** — while a buffer has unsaved changes, its text is copied to `~/.cache/binvim/recover/<hash>.json` every four seconds, and straight away when binvim is killed (`SIGTERM`), its terminal is closed (`SIGHUP`) or it crashes. Opening the file again puts that text back as unsaved changes and says so: `u` shows what's on disk, `:w` keeps the recovered text, `:e!` throws it away. The copy is removed once the buffer is written, reverted, closed, or quit with `:q!`. Until then, edits that don't open the file for you to see — `:S`, an LSP rename — leave it alone, and a second binvim opening a file the first still has unsaved changes to says so instead of taking them over. A `kill -9` loses at most the last four seconds; so does anything on Windows, where only the periodic copy runs. Buffers with no file name aren't covered. A `SIGTERM` or `SIGHUP` also saves the session, as it stood at the last copy; a crash doesn't, since the file that caused it would be reopened with it.
- **Recents in the file picker** — most-recently-opened files surface at the top of the file picker on an empty query, persisted at `~/.cache/binvim/recents`.

## Sessions and tabs

- **Sessions** — open buffers + per-buffer cursor + viewport persist to `~/.cache/binvim/sessions/<cwd-hash>.json` on clean shutdown, `SIGTERM` or `SIGHUP`, and restore on launch when no file argument is passed. Buffers whose paths no longer exist are silently dropped. Restored sessions drop you on the start page with the tab row above it advertising what's loaded — `H`/`L` (or `:bn`/`:bp`, `:b<n>`, a tab click) brings you into a buffer. Ex (`:`) and search (`/` / `?`) history rides on the same file (capped at 100 entries each, dedup against the immediate previous); `<Up>` / `<Down>` inside either prompt walks it, and the first `<Up>` snapshots whatever you'd already typed so walking off the bottom brings the draft back. Histories load even when you launch with `binvim foo.rs` — only buffer restoration is gated on a bare invocation.
- **Tab completion inside `:`** — `Tab` / `Shift-Tab` cycle candidates in the cmdline. Three modes picked by the head: command names before the first space (every alias the parser knows, filtered by prefix), filesystem entries after `:e` / `:edit` / `:w` / `:write` (directories get a trailing `/`, dotfiles hidden unless the basename starts with `.`), open-buffer basenames after `:b` / `:buffer`. Any other key drops the cycle so the next `Tab` re-derives candidates against the latest text.
- **Tab bar** — every open buffer renders as a tab at the top of the screen. Active tab in Surface1 + Lavender + bold, inactive tabs in Subtext0, dirty buffers carry a Peach `+`. Click a tab to switch; click its `×` to close (refuses dirty, same as `:bd`). `‹` / `›` chevrons appear at the bar edges when tabs scroll off either side. The bar matches the editor background.

## Pickers

Fuzzy file picker, live grep, recents, document / workspace symbols, code actions, references, and debug-project / debug-profile prompts — opened from leader (`<space>`).

- **File-type icons** — path-based rows (Files, Recents, Buffers, Grep, References) get a Nerd Font icon per row derived from `Lang::detect` on the basename; unknown extensions fall back to a generic document glyph. Symbol / Code-action pickers stay icon-free (rows aren't files).
- **Match-character highlighting** — fuzzy-matched chars render in Catppuccin Yellow + Bold so it's obvious which letters of your query produced the row's rank.
- **Navigation** — mouse wheel moves the selection by ±3; PageUp/PageDown jump a page; `Ctrl-U`/`Ctrl-D` jump a half-page; `Home`/`End` jump to first/last; `^J`/`^K` (and arrows) move by one.

Each picker is a centered floating popup with the directory part of paths dimmed and the basename bright.
